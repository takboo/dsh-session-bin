# Permanent session deletion: reference audit and DSH 0.2.0-rc.2 limits

This report records the **2026-10-07 source and publication inspection** of `MichengAI/dsh-archive-manager`, fixed at commit `46af4c54bab466b11ccddf2b63818749ded98c17`, and the resource contracts in this repository's exact public npm SDK, **DSH `0.2.0-rc.2`**. It distinguishes **source observation**, **design inference**, and **missing runtime proof**. Implementation status remains in the [README](../../README.md); selected product scope and admission conditions belong to the [design proposal](../design-proposal.md).

**Conclusion:** the reference is a published plugin implementing physical deletion through a custom JSONL adapter, private Workspace/Session/cache integration, and filesystem removal. It does not reveal a supported native permanent-deletion API in DSH `0.2.0-rc.2`. Its ordering, generation recognition, lifecycle identities, cache tombstones, and partial batch results are useful precedents. Its deletion path does not establish the writer, activity, ownership, shared-resource, or crash-recovery guarantees required by Session Bin. Recursively removing the JSONL session directory also removes the POSIX writer's stable `session.lock` inode. [Reference deletion][ref-delete], [physical removal][ref-removal], [SDK persistence limits][sdk-persistence-limits], [SDK writer lease][sdk-lease].

The original reference audit used primary GitHub source/API responses, npm metadata, and read-only inspection of the published tarball and locked SDK files. Tarball members were read in memory; no reference package was installed, built, imported, or executed. That audit performed no session operation or deletion test. The later independent admission probes below run public SDK owners in isolated temporary data; they do not perform erasure or reproduce the reference's deletion suite. Neither stage contacts the running `19387` GUI or operates on real user sessions. Upstream CI records below describe the reference project's executions.

## Deletion mechanism observed in the reference

The active Host installer preserves official Workspace/cache service objects and overlays methods and fields on them. The Workspace overlay copies methods from a subclass, modifies path accounting, adds Remote markers/binding, and restores installed methods on uninstall. The cache overlay installs a separate domain and write guards, with a fallback guarding the official table. This is native-service integration, not an independent plugin-owned Bin catalog. [Host installer][ref-install], [Workspace overlay][ref-overlay], [cache][ref-cache], [bundle patch][ref-patch].

The single-session endpoint uses Host-local `enqueueOperation()`. Its body checks `sessionKnown(id)`; unknown IDs receive cache/spill/Workspace/archive cleanup without first proving artifact absence. For live Sessions it awaits `flush`, obtains private `liveEntryFor`, and calls private `detachEntered`; older Hosts may temporarily prepare/enter/announce/detach cold Sessions. It then awaits optional cache `whenIdle`, deletes the cache row, attempts subagent/spill cleanup, removes the recognized JSONL directory or located artifact, and checks optional `stat(id)`. Finally it clears archive state, updates Workspace rows, forgets private indexes, saves the old `{ createdAt, cwd }` identity in a memory tombstone, and emits `api-session/removed`. Child/spill failures only warn. The result is `{ deleted: true }`, with no operation ID, persisted intent/phase, or historical receipt. [Deletion][ref-delete], [cold removal][ref-cold], [physical removal][ref-removal], [cascade/spill][ref-cascade].

**Additional source observation:** AgentLoop's own composite teardown cancels its exact machine, awaits `whenIdle()` and scope disposal, awaits its owned persistence handle `close()`, and only then detaches Agent/Session. **Admission conclusion:** no audited public owner can implement the proposed complete protocol on this SDK. The tests preserve all session directories, lock files, shared attachments and indexes. They do not validate erasure, shared-reference GC, index removal, actual Agent quiescence or crash recovery during deletion, and do not enlarge the product's supported deletion scope. Implementing a private `rm`/Workspace/cache overlay would leave the gaps unresolved.

**Locked declaration follow-up for native-archive authorization:** the concrete JSONL class does declare public `acquireWriteLease(header)` for created-session materialization, while `acquireLease`, `listGenerations` and `locate` are private in its published declaration. This local writer capability is not a verified lifecycle-bound, non-migrating retirement lease or full resource inventory. Workspace entity `detachSession(id)` removes an account member without touching the persisted transcript; SessionStore exact live entry/disposal likewise does not supply an awaited barrier for every resource owner. These partial capabilities leave the admission conclusion unchanged. ## Implications for Session Bin

**Design inference:** supported erasure needs a resource owner that can admit the exact lifecycle, exclude writers/new activity during retirement, preserve coordination identity, resolve exclusive/shared resources, and expose durable completion/recovery to Workspace/query/cache consumers. A stable upstream deletion/retention interface would be a stronger foundation than copying private overlays. This is an interface requirement inferred from the locked SDK, not a claim that such an interface exists. [Persistence limits][sdk-persistence-limits], [Session lifetime][sdk-session-runtime], [JSONL lease][sdk-lease], [attachments][sdk-attachments].

The project's boundaries remain: retire only a fixed observed native archive after explicit preparation and execution checks of membership, owner exact lifecycle and frozen scope; legacy Bin v1 journals keep their original authorization binding and recovery path. The native v2 binding is specified in the [Host contract](../host-lifecycle.md#原生归档单项删除准备与授权) and [ADR 0006](../decisions/0006-native-archive-retirement-binding.md). Observation and migration never mint deletion authority. Preserve activity refusal; support one Host owning native Workspace storage; use the same coordination directory for shared Bin backends; do not infer precise archive provenance during unobserved changes; and do not directly remove session directories, lock files, shared attachments, or private indexes to simulate a supported feature. Every new version/provider and resource-lifecycle protocol needs independent evidence. Another plugin's publication, declared range, and CI do not expand Session Bin's runtime support or authorize destructive testing. [Host contract](../host-lifecycle.md), [product/deletion admission](../design-proposal.md).

## 自实现 Adapter 的后续决定

The public SDK interface findings above remain valid. The user subsequently authorized implementing deletion inside this plugin instead of waiting for a native delete endpoint. [ADR 0007](../decisions/0007-native-jsonl-deletion-adapter.md) adopts a version/source-bound cold JSONL owner: exact physical inventory and content identities, existing stable lock exclusion, managed instance admission/read barriers, Workspace/cache medium convergence, and SQLite's own reconciliation transaction. It unlinks confirmed individual log files, retains directories/locks/shared attachment stores, and does not copy the audited references' recursive deletion or directly mutate private SQLite indexes. This is custom Adapter support with its own runtime evidence, not a new public DSH capability or a retroactive success claim for the earlier admission probes. The actual erasure, crash, UI and restricted combinations are recorded in the [Host verification](../verification/host-lifecycle.md) and [client verification](../verification/client-interface.md).
