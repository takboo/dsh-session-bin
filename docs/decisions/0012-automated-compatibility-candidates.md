# ADR 0012：自动检测与隔离候选验收

状态：已采用。日期：2026-10-27。

## 背景

精确版本与源码准入保护永久删除，但上游 npm、GitHub Release 和桌面发布渠道并不同步。仅运行当前 lockfile 无法证明新版兼容；仅改变版本/摘要也不能授予新组合生产资格。

## 决定

复用 dsh-usage-state 的发现、Issue 状态标记、有限重试和独立报告 job，每小时检测官方渠道，按精确版本与发布物 identity 去重。运行前写入持久化 running/attempt 状态，中断不视为通过，也不能无限重试。日志与报告 Artifact 保留 14 天，Issue 保留摘要。

在独立副本分别验证未改源码准入的正常构建和带显式标记的候选构建。候选副本可生成目标 SDK 版本/摘要映射，不能修改真实会话、durable 协议身份、运行时和平台资格，不能进入发布通道。关键源码变化仍须审阅；实际删除、活动保护、锁、资源和中断恢复断言继续执行。

机器人仅创建三份依赖文件的草稿 PR，不自动覆盖维护者分支，不自动修改生产准入、合并、打 tag 或发布。候选通过与正式组合验收分别记录；只有经审阅并独立验收的正式构建才能扩大生产支持。

## 代价与替代方案

每个新版需要独立准备测试环境；在同一每小时工作流中，匹配的官方 macOS ARM64 桌面发布物触发独立的签名、Electron/ASAR 和隔离候选验收。npm 与桌面组件分别记录身份、次数及原 run/source，后到桌面只补桌面，避免重复五平台计算；旧标记需一次验证迁移，不能推测历史完成状态。

所有候选结果最多是 partial，需要维护者判断。自动化只维护 Issue 与草稿 PR 的状态评论；正式源码与生产组合资格仍另行审阅，PR 不自动 Ready。拒绝自动刷新正式摘要白名单或通过环境变量开启未验证删除；这两种方案会混淆实验结果与生产授权。

流程与命令见[兼容性自动检查](../compatibility.md)。
