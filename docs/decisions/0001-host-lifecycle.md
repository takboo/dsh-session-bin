# ADR 0001：Host 回收站采用独立操作日志与保守恢复

状态：已采用，首个 Host 切片。目标 SDK：DSH 0.2.0-rc.2。

## 背景

[接口调研](../research/current-dsh-interfaces.md)与[兼容性验证](../verification/dsh-0.2-compatibility.md)证明原生归档、插件 sidecar domain 和独立插件加载可用，但归档与插件条目之间没有事务；原生归档没有 actor、操作回执或每个会话的版本。JSON 后端的进程内写入排序也不等于跨进程锁。SDK 当前的写入校验差异要求插件拥有自己的校验边界。

## 决定

使用公开 `storageDomain` 保存条目及不可重复执行的操作回执，所有写入先校验并取快照。`intent`、`applied`、`done` 区分意图、已确认原生操作和已提交插件结果；未确认的中断意图终止为冲突，只接受新的显式计划。启动恢复只改变插件元数据，不补偿或重放原生归档。

将观察到的所有权失效写入日志后再清理条目，恢复也读取已完成日志中的失效标记。操作结果保持历史语义，同一身份不能在恢复后再次执行旧移入请求。

一个 Host Module 串行协调请求，在 domain 打开前取得公开 POSIX `flock` lifetime lease，关闭 domain 后释放。共享 backend 必须使用同一协调目录；此锁只协调合作插件进程，支持范围限定为一个 Host 拥有原生 Workspace 存储。配置和确切行为见[Host 生命周期](../host-lifecycle.md)。

## 影响

故障恢复可能要求用户重新确认操作，这是缺少原生操作归属证据时的明确结果。该切片不能可靠识别停用或崩溃期间未观察的取消归档再归档；不因此声称精确归属。Windows 与多 Host 原生存储并发尚不在支持范围。永久删除需要另一套已验证的提供方与资源生命周期设计。

协议和恢复检查结果见[实现验证](../verification/host-lifecycle.md)。新增客户端应调用同一 Host Interface，不能重新在客户端组合原生变更与目录写入。
