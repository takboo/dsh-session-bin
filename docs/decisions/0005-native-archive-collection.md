# ADR 0005：原生 Archive 是唯一归档入口

状态：已采用。目标 SDK：DSH 0.2.0-rc.2。替代 ADR 0001 中以插件自有条目决定列表成员、恢复原先归档状态的产品语义；独立日志、保守恢复与 lifetime lease 继续适用。

## 背景

宿主已有 Archive、活动保护、停止确认与 Undo。独立“移入回收站”入口和插件目录要求用户再次操作已归档会话，形成两个归档集合。根据实际使用反馈，[已选定产品模型](../design-proposal.md#已选定的原生归档产品模型)要求插件直接管理原生归档集合。

## 决定

原生 `WorkspaceRegistry.archivedSessionIds` 是列表成员依据。插件不注册归档菜单，不替换原生方法或撤销交互；取消归档始终调用公开 `unarchiveSession`。选择、计划及回执绑定插件的观察身份，准备和执行再次复核成员与固定身份。

使用独立新版 sidecar 保存观察记录和取消归档 journal，保留原有 v1 Bin domain 及历史回执。旧条目不控制新版成员，也不把 `wasArchived` 带入新的取消归档语义。启动、兼容对账和未确认意图的恢复仅变更插件元数据；旧请求不重新归档或取消归档。旧浏览器待确认请求只查询历史回执，不重放旧变更。

归档观察不生成永久删除授权。既有删除 journal 的 guard、历史查询及同操作恢复继续保留；生产组合没有独立获准的原生 owner，继续拒绝新的原生永久删除。

## 影响

插件安装前的原生归档立即成为管理对象。批量只处理开始时固定的观察身份，已观察的取消归档再归档更换身份。宿主原生集合只有 ID，不提供归档时间或代际；观察身份不能证明 exact lifecycle，也不能识别停用或崩溃期间未观察的归档 ABA。列表因此不显示推测的归档时间。

严格 Remote 的变更与快照切换到 v2；旧 v1 只保留日志兼容路径。部署仍限一个 Host 拥有原生 Workspace 存储，遵守相同协调目录和已验证平台。正式行为见[Host 生命周期](../host-lifecycle.md)与[客户端接口](../client-interface.md)，运行证据见各自验证报告。
